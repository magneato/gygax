# Gygax 0.4.0: Matrix

Gygax 0.4.0 adds a visor. **glyder** puts a Gygax world in a VR headset: you see a simulation, or the real machines
connected to a node, laid out on a map table in front of you. Point at one and you drop into it at full scale. Fly it,
then press B to jack out, and its autonomy takes over again. It runs natively on Meta Quest (OpenXR on Vulkan, no
engine and no Java) and in a desktop window, and every Gygax simulation shares the same protocol and model kit.

Gygax is pre-1.0: interfaces may still change between minor releases, and the release notes will say how. Please
report what breaks: [issues](https://github.com/magneato/gygax/issues). 0.4.0 follows 0.3.0 "Skynet".

## glyder

```
$ ohflock --glyder
OHFLOCK in VR: open glyder on the headset and choose OHFLOCK (pairing code 482913).
  this computer:  192.168.1.20  (UDP 1999)
```

Put on the headset. The lobby (the Construct, a white void) lists the Gygax hosts on the network. Choose OHFLOCK,
enter the code, and the battle appears as a map table you can grab, turn and zoom. Point at a kite and pull the trigger. The view
switches at once. The kite finishes its current manoeuvre, then hands you the sticks, and the HUD shows what it is
finishing until it does.

* **Hosts:** `ohflock --glyder` and `wargames --glyder` publish their battles. You can take any kite, tank or drone,
  and the rest of the simulation carries on around you. `gygax serve --glyder` shows the machines registered with a
  node (`--device uav=mavlink:udp://0.0.0.0:14550`, placed on the map with `--glyder-origin LAT,LON`). With
  `--device-commands` you can drive them through the same gate the REST API uses.
* **Low latency:** your head motion is rendered locally from the headset's tracking and never waits on the
  network. World state arrives as self-contained 34-byte-per-entity snapshots with velocity, so a lost packet costs
  nothing. Host and client run the same handling code, so your stick input shows at once and the host agrees to
  within jitter. On a Quest 3S it runs at 120 Hz, with both eyes drawn in one multiview pass.
* **Paired, not open:** a six-digit code (or `--glyder-code`) derives a session key, and every packet carries an
  HMAC-SHA-256 tag, so nobody else on the LAN can drive a node or forge a handover. `--glyder-open` drops the code,
  for private networks only.
* **Your eyes:** enter a spectacle prescription and glyder sets the virtual cameras to your pupillary distance,
  turns each eye's view to match your prism, and pre-sharpens along your cylinder axis. That sharpening restores
  contrast for mild prescriptions (roughly ±1.5 D). You can type the prescription on a phone, on a page the headset
  serves only while the vision panel is open and only to the PIN it shows. The prescription never leaves the headset.
* **The kit:** one library of low-polygon models (aircraft, rovers, kites, vehicles), each generated from code at
  real-world size with no textures, and exportable as glTF for the web viewers.
* **No host? No problem:** the Construct carries its own small world, a rover, a quadcopter, a kite and a truck, so a
  headset is useful straight away. It runs over loopback on the same protocol as a real host.

glyder's portable core (protocol, kit, experience, prescription optics) builds and runs its tests with Gygax by
default. It needs no GPU or headset. The Vulkan renderer, the desktop viewer and the Quest app are opt-in builds
from `glyder/`:

```bash
cd glyder
cmake --preset desktop && cmake --build --preset desktop   # Vulkan + X11: build/glyder-desktop/glyder --demo
cmake --preset quest && cmake --build --preset quest       # with ANDROID_NDK_HOME set: a signed APK
```

The Quest build is a plain NDK build (no Gradle) that downloads the Khronos OpenXR loader, pinned by hash. Install
the APK with `adb install`. The standalone Quest APK (`glyder-0.4.0-quest.apk`, 1.0 MB) is attached directly to this
release and tracked in the repository under `glyder/`.

## Also in this release

* `gygax serve --device ID=KIND:URI` registers machines at start (repeatable).
* OHFLOCK can hand a kite to a human pilot (`Sim::setManual`, `steer`) and reports the satellites' positions from
  SatLink, so the headset shows the relay shell overhead.
* `GYGAX_BUILD_GLYDER` (on) builds glyder's core. The CLI and the examples link it.
* `scripts/lint.sh` covers glyder's sources.
* 426 CTest entries (44 of them glyder's) and 21 `gygax doctor` checks.

## Get it

| File | For |
| --- | --- |
| `gygax_0.4.0_amd64.deb` | Ubuntu 24.04+ or Debian 13+ on x86-64: `sudo apt install ./gygax_0.4.0_amd64.deb` |
| `gygax-0.4.0-Linux.tar.gz` | x86-64 Linux with glibc 2.38+ and GMP; unpack anywhere and run `bin/gygax` |
| `gygax-0.4.0-source.tar.gz` | Source of exactly this tag, glyder included |
| `glyder-0.4.0-quest.apk` | Meta Quest 3S / 3 / Pro standalone APK (120 Hz native OpenXR + Vulkan): `adb install -r glyder-0.4.0-quest.apk` |
| `SHA256SUMS` | Checksums for all release assets, for `sha256sum -c` |

Then:

```bash
gygax doctor                 # self-tests, no network needed
gygax serve --help           # --device and --glyder
```

**Other platforms:** macOS builds from source with Homebrew's LLVM, and the full test suite passes there in CI.
Windows 11 runs the same scripts through Docker Desktop (see `docs/WINDOWS.md`). Only Linux x86-64 has prebuilt
packages in this release.

## How it was checked

Every package attached here was built by this repository's release workflow from the tagged commit, after the full
test suite passed on that same machine. CI also runs every commit through Linux (clang 18 with lint, clang-tidy and
cppcheck), AddressSanitizer, ThreadSanitizer, a container health check and macOS.
